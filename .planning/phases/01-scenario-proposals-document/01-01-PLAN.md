SCENARIO-SPECIFIC AUTHORING NOTES:

AD-01 (Kerberoasting + AS-REP Roasting, Easy, 2 VMs): Name GetUserSPNs.py and Hashcat as the learning tools. Narrative: low-priv domain user, enumerates SPNs and accounts without pre-auth, requests tickets and AS-REP blobs, cracks offline.

AD-02 (LLMNR/NBT-NS relay, Medium, 2 VMs): Name Responder and ntlmrelayx. Narrative: AD environment with LLMNR enabled, broadcast poisoning captures NTLMv2 hashes, relay to SMB/LDAP executes commands without cracking. Keep distinct from NET-01 (per D-02: AD-02 emphasizes AD identity context; NET-01 emphasizes network SMB signing misconfiguration).

AD-03 (BloodHound ACL abuse, Medium, 2 VMs): Name BloodHound and SharpHound. Narrative: enumerate AD with SharpHound, visualize in BloodHound, identify WriteDACL or GenericWrite path, chain privilege escalation to Domain Admin.

AD-04 (ADCS ESC1, Hard, 2 VMs): Name Certipy. Narrative: misconfigured certificate template allows low-priv user to request a rogue cert for a privileged account, authenticate as Domain Admin via PKINIT.

AD-05 (Conti-style chain, Hard, 3 VMs) [Multi-step — 2 flags]: Name Responder, ntlmrelayx (first hop), Rubeus + evil-winrm (second hop). Two-hop narrative: LLMNR poisoning → SMB relay → foothold on pivot host [Flag 1]; Kerberoasting from pivot → offline crack → WinRM to DC [Flag 2]. Both lateral movement protocols must be distinct (SMB then WinRM).

NET-01 (SMB relay, Easy, 2 VMs): Name Responder and ntlmrelayx. Narrative: network where SMB signing is not enforced, relay captured hashes to access a target share — flag obtained without cracking the hash. Keep distinct from AD-02 (per D-02: emphasize network-layer SMB signing misconfiguration, not LLMNR/identity context).

NET-02 (mitm6 + LDAP relay, Medium, 2 VMs): Name mitm6. Narrative: rogue DHCPv6 server poisons IPv6 name resolution, WPAD authentication flows to attacker, relay to LDAP creates a new privileged domain account — zero malware, zero code execution.

NET-03 (ARP poisoning + MITM, Easy, 2 VMs): Name bettercap or sslstrip (pick one as the tool anchor). Narrative: ARP cache poisoning positions you as MITM, HTTP/S traffic is intercepted, plaintext credentials captured.

NET-04 (DNS cache poisoning, Medium, 2 VMs): Narrative: DNS resolver misconfiguration allows injection of forged responses, internal service request is redirected to attacker-controlled host, flag arrives in the intercepted HTTP request.

CVE-01 (EternalBlue MS17-010, Hard, 2 VMs): CVE number is CVE-2017-0144 (under bulletin MS17-010). Narrative: Windows 7 SP1 target running unpatched SMBv1, you author a Python exploit implementing the SMBv1 transaction setup and DoublePulsar shellcode staging using a provided protocol scaffold (mysmb.py) — the flag is obtained via the resulting shell.

CVE-02 (Log4Shell, Medium, 2 VMs): CVE number is CVE-2021-44228. Narrative: Java application logging attacker-controlled input via Log4j, you author a JNDI injection payload and a Python-based exploit chain server, OS command execution follows.

CVE-03 (Spring4Shell, Medium, 2 VMs): CVE number is CVE-2022-22965. Narrative: Spring MVC application, you craft an HTTP exploit that chains ClassLoader properties to deploy a JSP webshell via AccessLogValve — the webshell retrieves the flag.

CVE-04 (PrintNightmare, Medium, 2 VMs): Title MUST reference both CVE numbers: "PrintNightmare (CVE-2021-1675 / CVE-2021-34527)". Narrative frames the LPE path: you have a low-privileged shell on a Windows Server target, you author a C or Python payload that calls RpcAddPrinterDriverEx to load a malicious DLL as SYSTEM — privilege escalated, flag retrieved. Do NOT frame as remote code execution from an external attacker (that would be CVE-2021-34527 RCE path, inconsistent with the 2-VM standalone design).

CC-01 (IMDS SSRF, Easy, 2 VMs): Narrative: SSRF vulnerability in a web application, you craft requests that reach the simulated AWS IMDS endpoint (169.254.169.254), steal IAM role credentials, query a simulated S3 API to retrieve the flag.

CC-02 (Docker container escape, Medium, 2 VMs): Narrative: you land inside a deliberately configured privileged Docker container as root. From inside the container, you discover that the container's privilege level grants access to host kernel interfaces. You write a payload that abuses a cgroup notification path to execute commands on the underlying host and retrieve a flag planted in the host's root directory. Do NOT name "cgroup release_agent" in the description (that is Phase 3 kill-chain detail). Do NOT state which cgroup version. Frame only as "privileged container" + "host kernel interfaces" + "cgroup notification path."

CC-03 (Kubernetes misconfiguration, Hard, 2 VMs): Name kubectl. Narrative: over-privileged Kubernetes service account token, use kubectl to enumerate cluster resources, create a privileged pod with a hostPath volume mount, escape to the host node and retrieve the flag.

LLM-01 (Direct prompt injection, Easy, 2 VMs): Narrative: Ollama-backed chatbot with multiple defense layers (system prompt + regex filter + semantic validation), you chain at least two bypass techniques to override the system prompt and exfiltrate a hidden flag embedded in the LLM's context. Do NOT cite OWASP LLM category numbers.

LLM-02 (Indirect injection via RAG, Medium, 2 VMs): Narrative: RAG-enabled chatbot that ingests external documents into a vector database, you craft a malicious document, once ingested it plants injected instructions that trigger via a benign user query — the LLM outputs the flag. Do NOT cite OWASP IDs. Frame around the RAG/vector database attack surface, not "insecure output."

LLM-03 (IDOR in chat history API, Medium, 2 VMs): Narrative: LLM application with an unauthenticated or weakly-authenticated chat history endpoint, you enumerate conversation IDs via IDOR to reach a privileged user's session containing the flag.

ATP-01 (HAFNIUM-style, Hard, 3 VMs) [Multi-step — 2 flags]: Narrative: SSRF in a web app reaches an internal service, webshell upload achieves code execution, harvested credentials grant WinRM access to a pivot host [Flag 1]; from the pivot you enumerate domain resources and reach the domain controller [Flag 2].

ATP-02 (SolarWinds-style supply chain, Hard, 3 VMs) [Multi-step — 2 flags]: Name dnscat2 or iodine (pick one). Narrative: you compromise a simulated software update server, plant a backdoored update that executes on a downstream target [Flag 1]; from that foothold you establish a covert DNS tunneling C2 channel to reach an isolated final target and retrieve [Flag 2].

ATP-03 (LAPSUS$-style cloud identity, Hard, 3 VMs) [Multi-step — 2 flags]: Name kubectl. Narrative: SSRF in a cloud-hosted application reaches the IMDS endpoint and leaks a Kubernetes service account token, you use the token to enumerate cluster resources, escape to a privileged pod [Flag 1]; from the node you query etcd directly to extract stored secrets, authenticate as admin on the final target, and retrieve [Flag 2].

ATP-04 (Volt Typhoon living-off-the-land, Hard, 3 VMs) [Multi-step — 2 flags]: Name mitm6 and evil-winrm. Narrative: purely living-off-the-land — you deploy mitm6 with LDAP relay to create a privileged domain account without touching malware, use the account to WinRM into a pivot host [Flag 1]; from there you perform Kerberoasting, crack the service hash offline, and use the ticket for lateral movement to the domain controller via a second protocol [Flag 2].
